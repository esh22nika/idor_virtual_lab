Root Cause Analysis
  • Omission of Server-Side Authorization: The API endpoint relies on authentication to verify the user's presence, but assumes any logged-in user can access any record ID.
  • Client-Side Trust: Direct object references from URL parameters (/api/documents/<id>) are treated as authorized requests without verifying object ownership.
  • Broken Horizontal Boundaries: The application lacks tenant- or user-level segmentation at the database query layer.
Remediation & Lessons Learned
  • Bind Queries to Session Identity: Always include owner_id = session['user_id'] in the SQL WHERE clause.
  • Enforce Server-Side Checks on Every Request: Authorization logic must never live only in frontend JavaScript or UI button visibility.
  • UUIDs Are Not Access Control: Unguessable identifiers provide defense-in-depth against enumeration, but do not replace authorization.
  • Fail Closed: If an authorization check fails, return an explicit HTTP 403 Forbidden or non-disclosing 404 Not Found.
