Attack vs. Defense: Architectural Model
Concept Architecture

Mode A: Insecure Direct Object Reference (Vulnerable)

Flawed

The client changes the document ID in the URL. The server authenticates the user, but queries the resource by ID alone without checking who owns it.

# Client: Alice (User ID 1) requests Bob's doc (ID 201) GET /api/documents/201 HTTP/1.1 Cookie: session=Alice_Session_Token # Flawed Backend Query (Omits ownership check): SELECT * FROM documents WHERE id = 201; # RESULT: 200 OK • Bob's confidential draft leaked to Alice!

Mode B: Enforced Object-Level Authorization (Secure)

Defended

The server authenticates the user and binds the database query to the session identity, or validates that the resource owner matches session['user_id'].

# Client: Alice requests Bob's doc (ID 201) GET /api/documents/201 HTTP/1.1 Cookie: session=Alice_Session_Token # Secure Backend Query (Session-Bound): SELECT * FROM documents WHERE id = 201 AND owner_id = session['user_id']; # RESULT: 403 Forbidden • Horizontal escalation blocked!
